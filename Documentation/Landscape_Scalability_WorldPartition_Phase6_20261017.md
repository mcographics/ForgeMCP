## Implementation

ForgeMCP exposes five typed MCP operations for Landscape work: `unreal_inspect_landscape`, `unreal_preview_landscape`, `unreal_apply_landscape`, `unreal_landscape_job_status`, and `unreal_cancel_landscape_job`. The typed request actions are `create`, `raise`, `lower`, `flatten`, `smooth`, `generate`, `apply_heightmap`, `coastline`, `frame`, `save`, `reload`, `load_region`, and `unload_region`. These are native Unreal operations; no mouse automation, editor UI simulation, Blueprint-only terrain path, or unrestricted script execution is involved.

Creation uses `ALandscape::Import` with valid Unreal subsection configurations and a native `ForgeTerrain` Edit Layer. Creation itself currently imports a complete bounded height plane synchronously; only post-creation height editing is staged. The 2,041² test import took about 2.13 seconds. Bounded editing reads and writes through `FLandscapeEditDataInterface` on the editor game thread. The implementation validates topology, request dimensions, finite values, local height range, target world/map, PIE state, loaded components, and height readback. Terrain batches run from the editor tick, write at most eight rows per tick, request layer recomposition, and redraw editor viewports. Each job retains a verified raw R16 before-image; cancellation stops future batches and reports the applied partial result rather than silently rolling completed rows back.

The native World Partition path creates an isolated partitioned test world, enables streaming, and calls `ULandscapeSubsystem::ChangeGridSize` to form `ALandscapeStreamingProxy` actors. It inspects proxy descriptors and loaded states, and uses `UWorldPartitionEditorLoaderAdapter` shape loaders for region load/unload requests. The revised unload job keeps its adapter alive while polling matching proxy descriptors, and reports `unloaded` only after the observed descriptors transition; timeout and cancellation leave a truthful transition state. This logic compiled but still needs a live acceptance run. Saving verifies backups for the map and loaded Landscape external actor packages before saving. Reload uses `UEditorLoadingAndSavingUtils::LoadMap` and compares Landscape identity and height data.

An isolated development host may now start from Unreal's exact `/Engine/Maps/Entry` asset. Creation accepts it only when its package is clean, has no streaming sublevels, and does not use external actors; applying `create` still replaces it with a newly created empty disposable test world before spawning a Landscape. This supports headless project startup defaults without permitting edits to an arbitrary world.

The relevant engine APIs are documented by Epic: [ALandscapeProxy::Import (UE 5.6)](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Landscape/ALandscapeProxy/Import?application_version=5.6), [ULandscapeSubsystem (UE 5.6)](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Landscape/ULandscapeSubsystem?application_version=5.6), and [World Partition (UE 5.6)](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine?application_version=5.6). World Partition stores actors in grid cells and uses streaming sources to determine which cells load; creating proxies alone does not establish that unload behavior works in this Editor test.

## Resource bounds and topology

The current implementation accepts section quad sizes `7`, `15`, `31`, `63`, `127`, and `255`; one or two sections per component; up to 1,024 components per Landscape; up to 8,192 vertices on an axis; and at most 4,194,304 height samples per Landscape creation. Terrain edit regions and World Partition loader regions are each limited to 1,048,576 samples per request. Explicit `apply_heightmap` input is capped at 32,768 samples per chunk (a square chunk can be at most 181 × 181), but ForgeMCP does not yet provide a large-source tiled heightmap import/orchestration workflow. Staged edit before-and-after buffers share a 16 MiB budget; retained pending preview plans are limited to 15 MiB; and each tick writes no more than eight rows. These are ForgeMCP resource limits, not claims about Unreal Engine's absolute Landscape maximum. They bound plugin-owned raw height working sets; they do not measure all engine, render, or collision memory.

The proposed 18 × 18 components with 254 quads per component is a valid arithmetic Landscape layout: `18 × 254 + 1 = 4,573` samples per side and 324 components. It does not fit the current data budget:

| Measure | Proposed topology | Current ForgeMCP bound |
|---|---:|---:|
| Height samples | 20,912,329 | 4,194,304 |
| One R16 height plane | 41,824,658 bytes (about 39.9 MiB) | 8,388,608 bytes (8 MiB) |
| Before + after R16 buffers | 83,649,316 bytes (about 79.8 MiB) | 16 MiB |
| Components | 324 | 1,024 |

So the component count is allowed, while the height-sample count is about five times over the current cap. At 100 cm XY spacing, 4,573 samples span 4,572 m. One such landscape does not cover a 9 km × 9 km world. Treating the nine conceptual 3 km regions as nine copies would require 2,916 components and a separate tile workflow with shared-border rules, which ForgeMCP does not implement or validate. A lower-resolution 2,041-sample landscape can span roughly 3 km at about 147 cm XY spacing, but the current creation path creates one Landscape in one new test map; it does not stitch multiple Landscapes or validate shared borders between tiled maps.

## Remaining limits and city readiness

Phase 6A bounded single-Landscape construction and regional editing are usable for further isolated testing. Phases 6B and 6D are partial: the native editor loader APIs are wired and region requests complete, but Editor-side proxy unload and loaded/unloaded boundary behavior did not occur in the tested 4- or 18-component grids. Consequently, cross-streaming-boundary height edits, collision behavior while proxies transition, and streaming responsiveness are not accepted. Full-field coastline collision validation also failed at 1,009² despite successful height readback. Multi-Landscape tiling, shared-border continuity, a 4,573² Landscape, and a complete 9 km × 9 km terrain are unsupported by the current ForgeMCP budget/path.

**City-world readiness: not ready.** Do not use this candidate for `L_City_World_Master`. Before city-scale work, the implementation needs a separately designed and tested streamed/tiled data path that stays within bounded memory, shared-border continuity tests, reliable loaded/unloaded proxy transitions, successful large-region collision validation, and performance measurements including memory and frame responsiveness. No city terrain construction has begun.
